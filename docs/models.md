## Диффузионные модели

GGUF-Next не проверяет `general.architecture` по белому списку. Если твоя версия ComfyUI поддерживает модель, её GGUF загружается: ComfyUI определяет модель по именам тензоров. Неизвестная строка архитектуры даёт предупреждение в логе, не ошибку.

Примеры: Flux 1/2/3, Chroma, SD3.x, AuraFlow, HiDream / HiDream-O1, Cosmos / Anima, LTX-Video / LTX-2.x (AV), HunyuanVideo 1/1.5, Wan 2.x, Lumina 2 / Z-Image, Qwen-Image 1/2.1, Kandinsky 5, MiniMax H3, Krea 2, Ideogram 4, Omnigen2, Mochi, PixArt, HunyuanDiT.

GGUF без метаданных (stable-diffusion.cpp и другие конвертеры) сначала проверяются по отпечаткам ключей из `tools/convert.py`. Если отпечаток не подошёл, решает детект ComfyUI.

Проверено на реальных файлах:

| Файл | Что проверено |
| --- | --- |
| Anima turbo Q4_K_M | полная генерация, совпадение с оригиналом бит-в-бит, LoRA, TorchCompileModel, запуск через сервер ComfyUI |
| LTX-2.5 Distilled Q4_K_M | детект `LTXAV`, полная генерация видео по тексту с GGUF-энкодером Gemma 4 |
| MiniMax H3 Q4_K (без метаданных, sd.cpp) | детект `MiniMaxH3`, полная генерация видео по тексту с GGUF-энкодером Qwen3-VL-32B. city96 и Nif00 падают с «unknown architecture» |

Проверено на реальных файлах:

| Файл | Что проверено |
| --- | --- |
| Qwen2.5-VL-7B Q4_K_M + mmproj | кодирование промпта совпадает с оригиналом бит-в-бит |
| Qwen3-VL-32B UD-Q2_K_XL + mmproj (MiniMax H3) | 902 тензора, ни одного пропущенного или лишнего ключа, кодирование, генерация MiniMax H3. city96, leejet и Nif00 на этом файле падают |
| Gemma 4 12B Q5_K_M (LTX-2.5) | 682 тензора, ни одного пропущенного ключа, кодирование, генерация LTX-2.5. city96, leejet и Nif00 на этом файле падают |

На карте с 4 ГБ энкодер Gemma 4 12B для LTX-2.5 работает только на CPU, с `--novram` (около 4 минут на промпт на ноутбучном процессоре). Ограничение в коде энкодера ComfyUI, а не в паке GGUF: он дополняет промпт до 1024 токенов, хранит выходы всех 49 слоёв и склеивает их. Даже совсем без весов на GPU это требует больше 3.7 ГБ, и `--reserve-vram` не помогает. Qwen3-VL-32B для MiniMax H3 на той же карте работает на GPU в автоматическом режиме, пик 2.8 ГБ.

### mmproj

Qwen2.5-VL и Qwen3-VL нужен файл `mmproj-*.gguf` в той же папке, что и энкодер.

- Загрузчик сравнивает имена файлов без суффикса кванта: `Model.Q4_K_M.gguf` находит `Model.mmproj-f16.gguf`.
- Если имена не совпали и в папке ровно один `mmproj`, он берётся, только если его `clip.projector_type` подходит к энкодеру.
- Без `mmproj` Qwen2.5-VL загружается с предупреждением: текст работает, картинки на вход нет. Qwen3-VL без `mmproj` не загружается.

## Ограничения

- Qwen3.5 (гибридное линейное внимание), GPT-OSS (MoE) и Gemma 4 в раскладке тензоров llama.cpp не преобразуются в раскладку HF. Они загружаются только из GGUF с именами тензоров ComfyUI.
- Файл с именами llama.cpp и неизвестной архитектурой не загружается: загрузчик выдаёт ошибку, а не модель со спутанными весами.
- Большие токен-эмбеддинги (64k строк и больше) деквантуются в fp16 при загрузке, как в оригинале. Генерация с общими весами эмбеддинга идёт через cast ComfyUI, который не читает квантованные данные.
